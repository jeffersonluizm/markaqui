## Controle de Versão

Controle de Versão

O controle de versão do projeto é realizado utilizando Git, garantindo rastreabilidade, organização e qualidade no desenvolvimento do software. Abaixo estão as diretrizes adotadas.

 Estrutura de Branches
Branch	Objetivo
main	Versão estável e testada; pronta para produção.
unstable	Versão instável, integrada, mas ainda em validação.
testing	Branch destinada a testes de funcionalidades antes da integração final.
dev	Branch de desenvolvimento contínuo, onde novas funcionalidades são implementadas.

Fluxo de integração:
Desenvolvedores realizam commits na branch dev.
Funcionalidades completas seguem via pull request para testing.
Após aprovação e testes, o código é integrado à main.

 Regras de Commits

Mensagens claras e descritivas.
Referência à issue correspondente (ex.: #12).
Pequenas alterações por commit para facilitar revisão.
Exemplo de commit:
feat: adicionar tela de login #12

 Merges e Pull Requests
Pull request da branch dev para testing.
Revisão obrigatória por outro membro da equipe.
Apenas código testado e aprovado segue para main.

Versionamento e Tags
Seguindo versionamento semântico:

Tipo	Descrição	Exemplo
Major	Alterações grandes e incompatíveis	v2.0.0
Minor	Novas funcionalidades compatíveis	v1.1.0
Patch	Correções de bugs e pequenas melhorias	v1.1.1

Fluxo de versões:

v1.0.0 → v1.1.0 → v1.1.1

Gerência de Issues
Cada tarefa/problema registrado como issue no GitHub.
Vinculação de commits às issues correspondentes.
Fluxo de acompanhamento: To Do → In Progress → Done.
Uso de etiquetas (labels) para identificar tipo da atividade: bug, feature, documentation.

Introdução

Este relatório apresenta os principais indicadores de desempenho da equipe do Projeto Markaqui, com o objetivo de avaliar produtividade, qualidade do produto, retrabalho e horas trabalhadas pelos integrantes. Os dados foram simulados para análise e apresentação no contexto do curso de Análise de Sistemas.

Indicadores da Equipe
Horas Trabalhadas
Mostra o total de horas dedicadas por cada integrante.
Observação: Kauã Eduardo Silva teve a maior carga horária (14h) e Bruno Pereira Figueiredo a menor (8h).
Retrabalho (%)
Indica a porcentagem de tarefas que precisaram ser refeitas.
Observação: Kauã apresentou maior retrabalho (33%), enquanto Levi, William e Welder não tiveram tarefas refeitas.
Qualidade (%)

Mede a proporção de tarefas concluídas sem necessidade de retrabalho.
Observação: Maior qualidade observada em Levi, William e Welder (100%), menor em Kauã (66%).
Rendimento (tarefas/hora)
Avalia a produtividade da equipe, considerando o número de tarefas concluídas em relação às horas trabalhadas.
Observação: Levi Alves de Oliveira Neto apresenta maior rendimento relativo (0,4 tarefas/hora), enquanto Kauã, apesar de maior carga horária, tem rendimento menor (0,43 tarefas/hora).

Horas Trabalhadas por Integrante

As horas trabalhadas representam o tempo dedicado por cada integrante ao projeto.
Permitem avaliar o esforço individual e a distribuição de tarefas.
Maior carga horária indica maior comprometimento ou responsabilidades adicionais.
Menor carga horária pode indicar menor participação ou tarefas menos complexas.
Esse indicador ajuda a equipe a equilibrar o trabalho nas próximas etapas.

### Ferramentas

As ferramentas empregadas no projeto foram escolhidas para atender às necessidades da equipe e facilitar o desenvolvimento do sistema, garantindo produtividade, organização e qualidade.

Editor de Código

VSCode: utilizado para edição de código, com integração ao Git e experiência prévia da equipe.
React Native: framework para desenvolvimento de aplicações móveis multiplataforma.
Android Studio: utilizado para emular e testar aplicativos Android de forma eficiente.

Ferramentas de Comunicação
Microsoft Teams: plataforma principal de comunicação e reuniões online.
WhatsApp: suporte para mensagens rápidas e alinhamento das tarefas diárias.
Ferramentas de Desenho de Tela (Wireframing)Figma: utilizado para prototipagem das interfaces, permitindo organizar e validar telas antes do desenvolvimento.

Ferramentas de Gerenciamento

GitHub: controle de versão, gestão de issues e acompanhamento do progresso.
Slack: comunicação rápida e integração com gerenciamento de tarefas.
